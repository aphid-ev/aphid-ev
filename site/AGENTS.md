# Site guidelines

aphid site for bladlus.se: blog posts are the build log, wiki pages are the
reference documentation. aphid's own content and theme conventions are in the
`aphid-content` and `aphid-theme` skills under `.claude/skills/`, generated by
`aphid agent claude`. After bumping `aphid_version` in the root justfile,
regenerate them in a scratch directory and copy the skills here; do not keep
the `CLAUDE.md` it writes. This file only covers what is specific to the
monorepo.

- This is where documentation goes. When code, hardware or wiring changes in a
  way a reader would care about, update the matching wiki page in the same
  commit.
- `static/generated/` is produced by `just artifacts` from the KiCad projects
  and the wirebug model. Never edit or commit files there; change the source
  and regenerate. Reference them by their `/static/generated/…` path.
- Facts that are defined in code (CAN messages, parameters, pinouts) should be
  generated or linked, not retyped. If a page needs a table that only exists
  in code, say so instead of copying values by hand.
- Vendor datasheets and CAD files are kept outside the repository. Copy the
  relevant facts into a wiki page and cite the source.
- Run the `unslop` skill over any prose you write or rewrite here before
  committing it. Apply it to your own text only; leave the user's wording and
  their blog posts as they are unless asked to edit them.
- `just site build` must pass: aphid fails the build on broken wiki-links.

## Wiki-links

aphid slugifies the text inside `[[ ... ]]`: lowercase, spaces become hyphens,
hyphens stay.

- Write multi-word slugs in prose form: `[[VCM requirements]]`, `[[EV-CAN]]`,
  `[[HV system]]`, not `[[vcm-requirements]]`. The href and the display text
  come out the same, since the display text is the target's `title`.
- Never use `[[slug|display]]` in a table cell; the `|` ends the cell. Use the
  bare form and let the title fill the column. If the title doesn't fit,
  rename the page.
- Outside tables, drop `|display` when the title reads well in the sentence.
  Keep it when the title is too long inline (`[[pdm|PDM]]`), when the phrase
  adds context (`[[pdm#dcdc|DC/DC built into the PDM]]`), or to keep a list of
  short references parallel.
- A wiki slug is the filename. Keep it short: `motor.md`, not
  `nissan-leaf-em57-motor.md`. The long form goes in `title`.

## Images

- A blog post's `image:` is the post hero and the blog index thumbnail. Export
  it at 1920 × 960, a 2:1 ratio, as WebP at quality 80 and under 250 KB. The
  hero is cropped to 480 px high with `object-fit: cover`, so keep the subject
  centred.
- Use WebP for photos. Keep PNG for diagrams with hard edges or small text
  (`vcm_pinout.png`) and for `static/logo.png`, the favicon source.
